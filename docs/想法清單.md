## 各項內容與評估

### 1. 跳躍與翻滾
**想法**：角色要能跳，能翻滾閃避，翻滾有極短的無敵幀。

**評估**
- 翻滾：現有架構直接做得到（類似盾擊衝鋒的位移，加上無敵計時）。規模小。
- **跳躍是架構問題**：目前模擬層只有平面座標（XZ），沒有「高度」。要能跳，就要在模擬層加入高度與重力；命中判定也要考慮高度（跳起來能不能躲過橫掃、空中能不能被打到）。這會一路影響第 5、7 點（第 7 點提到的「來自天空、地下的攻擊」也需要高度）。
- 建議：**在做多人連線之前決定要不要有高度**。連線要同步的資料會因此改變，連線做完才加，要回頭改的地方比較多。

### 2. 單人與多人（2~4 人）
**想法**：要有單人模式跟多人模式，多人模式是 2~4 人。

**評估**
- 已經是既定方向（`PROJECT_GUIDELINES.md` 15.1、15.7：房主當伺服器、合作 1~4 人），目前的架構從第一天就照這個分層。單人就是「沒有其他人連進來的房主」，不另寫一套。
- 待問：敵人依人數調整、誤傷、倒地救援、中途加入、命中停頓（已記在 `進度.md`）。

### 3. 大量物品的資料庫
**想法**：未來可能會有非常多的裝備、武器、道具、消耗品，所以是不是要先建好資料庫？

**評估**
- 目前武器、技能是寫在程式裡的資料表（`godot/defs/*.gd`），數量少時很好用；上百件以後會難以管理。
- 值得先定下來的是「**物品的資料格式與唯一編號**」：存檔、連線同步、掉落表、商店都靠編號找物品。格式定好，之後新增物品只是加資料，不用改程式。
- 做法選項（之後再決定）：Godot 內建的 Resource 檔（可在編輯器裡填表）、試算表匯出、或維持程式資料表。不需要真的架資料庫伺服器。
- 建議：和第 4 點一起規劃（裝備、技能、天賦常常互相引用）。

### 4. 成長與 build 系統
**想法**：天賦、升級、職業、技能、武器技能、甚至接技，都是我會考慮加進去的。

**評估**
- 和 `設計方向.md` 的「重玩動機：不同 build 和職業」「遊戲外的永久成長」方向一致。
- 要先分清楚兩種成長：**局內**（每局從頭開始的升級、技能選擇）與**局外**（永久天賦、解鎖）。局外成長需要存檔。
- 「接技」與第 6 點的動作系統綁在一起。
- 規模大，建議拆成多個小步驟，先做骨架（例如「經驗與升級三選一」），再逐步加入。

### 5. 怪物改成用招式攻擊
**想法**：怪物想要改成沒有碰撞傷害，應該要讓所有怪物都有自己的攻擊模組，怪物攻擊到玩家，玩家才會受傷。

**評估**
- 目前小怪靠「貼到就扣血」，Boss 已經是招式制（重砸、衝鋒）。改法是把小怪也換成「預備動作 → 判定 → 收招」的招式，玩家能看預備動作閃避。
- 這和「戰鬥重點：閃避走位」一致，也會讓第 1 點的翻滾、第 7 點的格擋有意義。
- 建議先做一套**通用的攻擊判定**（判定範圍的形狀、方向、高度、能不能被格擋），玩家與怪物共用。第 1、5、6、7 點都會用到它。

### 6. 玩家攻擊動作
**想法**：玩家操作的角色的攻擊動作我希望可以很流暢且酷炫，目前只有普攻是手揮動一下而已，未來不可能只有這樣。

**評估**
- 目前動作是程式算出的關節角度（照網頁版），適合簡單揮擊，做不出複雜連招。
- 要達到流暢酷炫，通常需要：用 Godot 內建的動畫工具（AnimationPlayer / AnimationTree）製作關鍵影格動畫，加上特效（揮砍弧光、殘影）、命中停頓、鏡頭震動。特效目前還沒從網頁版搬過來。
- 這是美術工作量最大的一項。可能要決定：自己做動畫、使用現成動畫素材，或保持程式動畫但加強。要用哪種角色模型（目前是程式生成的低多邊形）也會影響做法。
- 建議：先用一把武器做出一套「看起來夠好」的範例，確定做法後再推廣。

### 7. 劍盾右鍵：格擋與盾反
**想法**：現在的雛形的劍盾的右鍵太廢了，我想要先至少改成格擋反擊。
- 按右鍵防禦來自前方 75 度角的攻擊，持續 3 秒。
- 極短時間內瞬間防禦攻擊成功的話，會觸發盾反傷害，對前方一定範圍內的敵人都造成傷害。
- 注意盾牌只能擋前方，來自天空、地下、或是角度外的攻擊都無法擋住。

**評估**
- 需要每次攻擊都帶有「從哪個方向來」與「攻擊種類（地面 / 空中 / 地下）」，正好就是第 5 點的通用攻擊判定。
- 待使用者決定的細節（做的時候再問）：「75 度」是左右各 37.5° 還是各 75°；「持續 3 秒」是按住最多 3 秒還是按一下自動維持 3 秒；格擋時能不能移動；「極短時間」的完美格擋窗口要幾秒；盾反的傷害、範圍、冷卻；目前的盾擊衝鋒是否保留。
- 屬於核心玩法，做之前要先寫進 `設計方向.md`。

## Claude 的初步排序建議（使用者還沒決定）
1. 先在桌機試玩，確認階段一的手感（數值已經對齊網頁版）。
2. 聽完第 8 點後，整理成「一句話介紹 / 參考作品」等設計方向。
3. **連線之前先定架構**：要不要有高度（第 1 點）、通用攻擊判定（第 5、7 點）、物品資料格式（第 3 點）。這三件事會改變連線要同步的資料，先定好最省工。
4. 再做多人連線（第 2 點）。
5. 之後依設計方向，逐步加入成長系統（第 4 點）、動作與特效（第 6 點）、更多內容。
