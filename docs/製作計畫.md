# 製作計畫

> 把 `docs/設計方向.md` 拆成一個個**做完就能自己驗收**的小里程碑。每一步都寫：做出什麼、使用者怎麼驗證、`check.gd` 補什麼檢查、開工前要問什麼。
> 階段的先後順序是 Claude 的建議，**使用者還沒拍板**；要調整就直接改本檔。里程碑完成就**刪掉該段細節**，只在總覽表留版號（細節在 CHANGELOG、`docs/系統說明.md` 與 git 歷史）。
> 「你怎麼驗證」以**實際玩**為主，數字類的目標要附實測結果（規則見 `CLAUDE.md` 2.4）。

## 原則
- **一個里程碑 = 一個版號**，做完就能玩、能看到差別；看不到差別的底層工作（例如屬性系統），要附一個「除錯用」的看得到的方式（面板、除錯鍵）。
- **先單機、後連線，但資料形狀一開始就照連線規格**（`PROJECT_GUIDELINES.md` 第 16 節）：B 階段全部做完才接 C，因為跳躍高度、攻擊判定、物品編號都會改到連線要同步的資料。
- **實體用繼承、內容用資料**：種類不同的東西（玩家、敵人、投射物、可互動物件）用繼承；數量多、差在數值或效果的東西（武器、道具、詞條、怪物種類）用資料表 + 可組合的效果，不為每個道具寫子類別。
- 牽涉核心玩法的細節，開工前照「開工前要問」先問使用者，不自己決定。
