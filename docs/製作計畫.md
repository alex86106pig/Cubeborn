# 製作計畫

> 把 `docs/設計方向.md` 拆成一個個**做完就能自己驗收**的小里程碑。每一步都寫：做出什麼、使用者怎麼驗證、`check.gd` 補什麼檢查、開工前要問什麼。
> 階段的先後順序是 Claude 的建議，**使用者還沒拍板**；要調整就直接改本檔。里程碑完成就**刪掉該段細節**，只在總覽表留版號（細節在 CHANGELOG、`docs/系統說明.md` 與 git 歷史）。
> 「你怎麼驗證」以**實際玩**為主，數字類的目標要附實測結果（規則見 `CLAUDE.md` 2.4）。

## 原則
- **一個里程碑 = 一個版號**，做完就能玩、能看到差別；看不到差別的底層工作（例如屬性系統），要附一個「除錯用」的看得到的方式（面板、除錯鍵）。
- **先單機、後連線，但資料形狀一開始就照連線規格**（`PROJECT_GUIDELINES.md` 第 16 節）：B 階段全部做完才接 C，因為跳躍高度、攻擊判定、物品編號都會改到連線要同步的資料。
- **實體用繼承、內容用資料**：種類不同的東西（玩家、敵人、投射物、可互動物件）用繼承；數量多、差在數值或效果的東西（武器、道具、詞條、怪物種類）用資料表 + 可組合的效果，不為每個道具寫子類別。
- 牽涉核心玩法的細節，開工前照「開工前要問」先問使用者，不自己決定。

## H. 觸發袋（Build 第二次改版）
- 取代武器格子、副手、寶石座、部位、印記格、武器詞條、合成；數字都是 Claude 暫定。每步各自 commit，做完一步就刪細節、留一行。
1. **資料**：`defs/bag_defs.gd`（袋子種類、接哪一邊、對應原本的觸發時機）、道具分類（數值 / 效果 / 技能 / 修飾）、觸發道具對到哪個效果（`docs/道具清單.md` 的對照表）。不改玩法。
   - 檢查：每個道具都有分類；每個觸發道具都對到一個袋子與效果；主袋特殊的（守護亡靈、復活十字）不算效果。
2. **背包結構**：主袋 + 接在四邊的袋子（哪一邊、沿邊的位置、袋子形狀）、放置規則（數值只進主袋；效果、技能、修飾只進袋子）、快照；生效的道具改成主袋 + 袋子內容。武器格子、寶石座、副手停用。開局給主袋 + 按鍵袋 1（職業起始技能）+ 職業的小觸發袋。
   - 你怎麼驗證：開局按 Tab 看到主袋與袋子（畫面先用現有背包介面湊合，第 4 步才重做）；數值道具放主袋有效果。
   - 檢查：放置規則、袋子接邊與滑動、快照來回一樣。
3. **觸發**：普攻 / 右鍵的出手、命中、擊殺，受傷、翻滾、計時、數字鍵 → 發動袋裡的效果與技能；每個各自耗魔、不夠時由左到右；命中袋同一袋 0.3 秒一次；修飾作用在同一袋；技能不綁武器；袋子放出來的不再觸發袋子。
   - 你怎麼驗證：武器測試場左鍵命中袋放寒氣，打木樁時周圍冒冰；右鍵命中袋放技能，右鍵打中時自動放。
   - 檢查：每種袋子各發動一次、不會連鎖、魔力不夠時的順序。
4. **Tab 畫面**：主袋與四邊的袋子、拖曳放東西、接袋子與沿邊滑動、袋子上寫時機與按鍵、說明框。
5. **取得**：開局職業袋、菁英怪掉袋子、門的「袋子」獎勵、Boss 的大袋 / 倍率袋、祭壇 / 石棺的詛咒袋、鐵砧改造袋子（加大一格、換觸發、加倍率）或主袋 +1 行；遺物的選項改成技能 / 效果 / 數值 / 袋子。
   - 你怎麼驗證：玩一局 1-1~1-5，大約拿到 3~5 個袋子。
6. **同色區塊**：跨袋子算最大連通格數，門檻 4 / 8 / 12 格，取代件數。
7. **收尾**：拿掉舊程式（部位、印記格、詞條、合成、鍛造祭壇、副手）、連線同步、自動試玩機器人、量全場投射物上限與近戰 / 遠程平衡、圖鑑 artifact（道具、武器、遊戲機制）、`docs/系統說明.md` 新一節、`docs/道具清單.md` 重寫、試玩清單。
