# 角色選擇畫面（參考雨中冒險 2）— 改動計畫

> 2026-10-27 YangHsu 與 Claude 討論定案，交給另一個對話實作。做完後：規格搬進 `docs/系統說明.md` 新的一節、本檔刪除（git 歷史保留）。
> 開工照 `CLAUDE.md` 第 0 節；每一階段照 1.4 驗收、1.5 記 CHANGELOG 與 commit。

## 為什麼要改
- 使用者：現在的選職業頁（`MainMenu._class_card`，7 張卡兩排）**不夠有質感、資訊太密集**。
- 多人大廳的選職業只是連線面板（`NetPanel._class_row`）裡一排小按鈕，看不到彼此選了什麼角色。
- 目標：一個單人和多人共用的選角畫面，看得到角色本人，數值一眼比較得出差異，文字量比現在少。

## 版面（參考雨中冒險 2，最後由階段 0 的對比頁定）
- **左邊**：職業列表。頭像**先用文字**（職業名，之後再換圖）。
  - 死靈術士放一格**問號佔位**（鎖住、不能選、顯示「尚未開放」）。
  - 要有**未解鎖**狀態：鎖頭 + 解鎖條件文字（資料欄位見下面，目前 7 個都是解鎖的）。
- **中間**：3D 角色。
  - 先放**目前的模型**（騎士換色 + 起始武器）、靜止姿勢；亮相動作之後再加。背景**素色**。
  - **滑鼠拖動可旋轉**（只轉 Y 軸；不麻煩才做，卡住就先跳過並回報）。
  - 多人：所有人的角色**並排站**（最多 4 個），自己的在中間、比較大，頭上寫「P1 守墓騎士」；別人換職業時角色即時跟著換。
- **右邊**：選中職業的資訊。
  - 名稱、一句介紹（`pitch`）、起始武器。
  - **數值橫條圖**（見下面「數值圖」）。
  - 技能區（雨中冒險式，一格一招）：被動 / 左鍵 / 右鍵 / 翻滾，每格圖示 + 招式名 + 一兩句說明。
- **下方**：難度選擇、名單（多人）、**「開始」按鈕**（單人）或「準備好了 / 開始遊戲」（多人）。
  - **點職業只是選，要按「開始」才開局**（現在是點職業名稱直接開始，要改）。

### 不做（這次）
- 職業專屬造型、換技能 / 換造型（loadout）、鍵盤 / 手把切換職業、亮相動作。

## 數值圖
- 使用者：要畫「物攻、魔攻、防禦、運氣」這種**真實數值**的圖，不是手填評分；**資料直接從 `ClassDefs.CLASSES[id].stats` 讀**（沒寫的照 `StatDefs` 基準 / `Config.PLAYER`）。
- 形式：**橫條圖**（使用者 2026-10-27 同意）：一個數值一行，名稱 + 長條 + 數字，長條上畫**基準線**（`StatDefs` / `Config.PLAYER` 的基準值），高於 / 低於基準用不同顏色。切換職業時條子在同一位置伸縮，好比較。
  - 不用雷達圖（使用者決定，對比頁也不放）：讀不出數字、軸的順序會改變形狀觀感、8 軸太擠。
- 項目（Claude 提案，對比頁讓使用者確認）：生命 `max_hp`、物攻 `phys_damage`、魔攻 `magic_damage`、護甲 `armor`、魔抗 `magic_resist`、攻速 `attack_speed`、移速 `move_speed`、運氣 `treasure`（尋寶）。
  - 回復、閃避、爆擊傷害不上圖，和基準不同時列在圖下方一行小字。
- 正規化：**每一項固定的顯示範圍**（例如生命 60~140），寫成表（`ClassDefs` 或 UI 檔內的常數）。不用「全部職業的最小～最大值」：加一個職業會讓其他人的圖形一起變。
- 每一行右邊直接顯示實際數字。
- 注意：`max_hp`、`move_speed` 的基準在 `Config.PLAYER`（生命 100、`core/config.gd:49`），**不是 `StatDefs` 的 1.0**；職業資料的移速是絕對值（6.2、7.0）。沒寫的項目取基準時，這兩項照 `Config.PLAYER`，其他照 `StatDefs`。

## 難度（新功能，使用者 2026-10-27 決定）
- 三檔：**簡單 / 普通 / 困難**，只改**怪潮開始後的難度上升速度** ×0.75 / ×1 / ×1.5，其他都不動。預設普通。
  - 現在：`DigEvent.difficulty` = `world.base_difficulty + time × EventDefs.DIFFICULTY.per_second`（`sim/dig_event.gd:36`）。改成再乘難度倍率；倍率表放 `defs/event_defs.gd`。
- 多人：**房主選**，其他人看得到、不能改；跟著大廳廣播、開局帶過去（`NetSession._rpc_start` 已經帶 `lobby_choices`，照同樣方式加）。**客戶端一定會自己算難度**：快照只送 `event.time` 與 `base_difficulty`（`net/net_codec.gd:73,458`），HUD（`ui/hud.gd:422`）與回報文字（`ui/run_log.gd:131`）在客戶端的 world 呼叫 `world.difficulty()`，所以倍率要設進 `NetClient.world`。
  - Claude 決定：房主改難度時，客戶端的「準備好了」全部重設（大家是在舊難度下按的）。按了準備之後還能換職業（照現在的程式）。
- 「重新開始」保留選的難度（同 `World.player_classes`）。
- 遊玩紀錄的回報文字（`RunLog.report_text`）加上難度檔位，試玩回饋才分得出來。
- 啟動參數：仿 `--class=` 加 `--difficulty=easy|normal|hard`（網頁版 `?difficulty=`：要把 `difficulty` 加進 `debug/launch_args.gd:18` 的 `WEB_URL_ARGS` 白名單才會生效）。
- 這是數值平衡（`CLAUDE.md` 1.6），做完要在 `docs/設計方向.md` 的「難度」補一行。

## 流程
- **單人**：主選單「單人遊戲」→ 選角畫面 → 選職業、難度 → 「開始」→ `main.start_single(class_id)`（加難度參數）。「返回」回首頁。
- **多人**：主選單「多人遊戲」→（桌面版先選房號 / IP）→ 多人頁開房 / 加入 → **連上進大廳後直接切到選角畫面**（名單也在這頁）。
  - 連線面板（`NetPanel`）只留開房、加入、連線狀態；`_class_row` 與選職業按鈕**拿掉**，準備鈕和開始鈕搬到選角畫面。
  - 現有規則照舊（`docs/系統說明.md` §18「多人大廳（F3）」）：`NetSession.lobby_choices` 房主決定並廣播、新加入預設第一個職業、房主一律算準備好、全員準備好「開始遊戲」才能按。
  - **預選階段即時更新**：還沒按準備時換職業，其他人畫面上的角色與名單也要跟著換（`set_choice` 本來就會送，確認選角畫面有接 `lobby_changed`）。
  - 可以重複選同一個職業。
  - 「離開」回主選單（現有的離開連線流程）。
- 遊戲中 Esc 選單的連線面板只顯示連線資訊。
  - 例外：`--host` / `--join` 啟動會跳過主選單（`main.gd:93`），大廳顯示在 Esc 選單（標題「連線大廳」，`main.gd:439-448`）。目前只有自動驗證走這條（`--autostart` 不檢查準備）；拿掉 `_class_row` 後這條路也要能開局，最好也切到選角畫面，跟玩家走的路一致。

## 資料欄位
- `ClassDefs.CLASSES[id]` 加 `locked`（預設沒有 = 解鎖）與 `unlock`（解鎖條件文字）；`ORDER` 後面接一個佔位 `&"necromancer"`（`locked: true`、`unlock: "尚未開放"`，沒有 stats / weapon）。
  - 注意：`ClassDefs.ORDER` / `CLASSES` 被很多地方當「全部可選職業」用；佔位不能被選到、不能進 `apply_class`、不能拿去做 3D 預覽。建議另外放 `PLACEHOLDERS`（不進 `ORDER` / `CLASSES`）或讓用的地方濾掉 locked，實作者決定，但要有檢查擋住。已知會踩到的地方：
    - **連線的職業驗證（信任邊界，一定要擋）**：`net/net_session.gd:349`（`set_choice`）、`:361`（`_rpc_choice`）只看 `ClassDefs.CLASSES.has(...)`，客戶端送鎖住的職業也會被收下。改成「存在且沒鎖」。
    - `tests/player_checks.gd:783` 對 `ORDER` 每一個做 `apply_class`；`tests/view_checks.gd:308` 用 `ORDER.back()`。
    - `DarkFantasy.player_character` 讀 `.colors`（`view/styles/dark_fantasy.gd:61`）。
    - 大廳預設第一個職業、`--menu-flow` 用 `ORDER[0]`。
