# 系統說明

> 各系統的實作細節與使用者做過的決定（原 `PROJECT_GUIDELINES.md` 15.11~15.26，2026-10-26 搬來；§N = 舊的 15.(N+10)）。
> 共通規則（分層、命名、事件表、驗收）在 [`PROJECT_GUIDELINES.md`](../PROJECT_GUIDELINES.md)；要動某個系統時只讀那一節。
> 標題的版本號是該系統第一次做出來的版本，之後的改動寫在內文。系統有變時同步更新該節，新系統接在最後。

## §1 屬性系統（v0.14.0）
- 玩家與敵人共用一套屬性：名稱、基礎值、上下限、顯示方式在 `defs/stat_defs.gd`；計算在 `sim/stats.gd`，每個實體一個 `entity.stats`。
- **公式**：結果 = (基礎值 + Σadd) × (1 + Σpct) × Πmul，再取整（有 `round` 的屬性）、限制上下限。使用者決定：
  - 同類加成**相加**（兩個 +8% = +16%）。暫時效果（增益）、波次倍率、**冷卻縮減**用 `mul` **相乘**（−6% 與 −25% → ×0.94 × 0.75 = 0.705，疊再多也不會到 0）。
  - **護甲**：受到傷害 × 100 ÷ (100 + 護甲)（`StatDefs.ARMOR_SCALE`），護甲 100 減傷 50%。
  - **爆擊**：基礎爆擊率 0%、爆擊傷害 ×1.5；爆擊率 0 時不擲骰（不消耗 `world.rng`）。
- 加成以「來源」為單位整批設定 / 移除：`entity.set_stat_source(來源, [[屬性, Stats.ADD|PCT|MUL, 數值], …])`、`remove_stat_source(來源)`。來源名稱：增益用增益 id、盾擊 `shieldBash`、敵人波次 `wave`、除錯 `debug`；之後的道具用道具實例的 id。
- 最大生命提高時目前生命增加同樣的量；降低時只截到上限。
- 套用位置：攻擊力由出招方乘進 `hit.damage`（投射物在發射時就乘好）；爆擊與擊退在 `Combat.apply_damage`；護甲與受到傷害在 `Entity.take_damage`；攻速只除普攻三階段時間；冷卻縮減套在特殊技與數字鍵欄位；每秒回血在 `Entity.integrate`：`regen_block_timer` > 0 時不回，玩家受傷（`Player._on_damaged`）設成 `Config.PLAYER.regen_delay` 5 秒，職業、道具、詞條的回血都一樣；怪物不設、照常回（使用者 2026-10-29：回太快遊戲太簡單，職業回血減半 + 脫戰才回）。
- `Entity.max_hp`、`damage_mul`、`damage_taken_mul`、`knockback_mul`（受到擊退）與 `Enemy.speed` 是屬性的唯讀捷徑，不能直接賦值。
- 新增屬性時先加進 `stat_defs.gd`；對應系統還沒做的屬性設 `in_use = false`（屬性面板不顯示）。
- **屬性面板**（`ui/stats_panel.gd`）：依 `StatDefs.PANEL_GROUPS` 分組（生存、攻擊、移動與冷卻、探索、羈絆）；`PANEL_CORE` 的 7 個（最大生命、護甲、攻擊力、攻速、爆擊率、爆擊傷害、移速）一直顯示，其他只在不是基礎值時顯示，整組都沒顯示就連標題一起藏（全部列出來 42 列太滿，使用者 2026-10-31 決定）。新增 `in_use` 的屬性要放進其中一組，檢查「背包介面」會擋。
- **傷害類型與招式傷害（F1，2026-10-26）**：
  - 每把武器一個 `base_damage` 與 `damage_type`，招式用 `damage_pct`（基礎傷害的倍率）。招式傷害 = 基礎傷害 × 招式 % × 攻擊力 × 物理 / 屬性傷害（`Player.move_damage`；不含屬性的值 `WeaponDefs.move_base_damage`）。劍盾 12 物理（普攻 100%、第三段再 × 1.8、盾反 200% = 24，原本固定 25，使用者同意）；法杖 8 秘術（魔彈 100%、奧術爆裂 350% = 28）。
  - 「攻擊力」（`damage`）保留成全部傷害的倍率（道具、武器稀有度與詞條、怪物難度照舊用它）；「物理傷害」只乘物理、「屬性傷害」（`elem_damage`）乘物理以外的全部屬性，給職業與之後的道具用。
  - hit 帶 `damage_type`（投射物、爆炸跟著發射時的類型），沒帶 = 物理。
- **傷害屬性與抗性（Build 改版第 1 步，2026-10-30 許家慶決定方向，數字 Claude 暫定）**：取代原本的物理 / 魔法兩類。
  - 8 種屬性 `StatDefs.DAMAGE_TYPES`：物理 `phys`、火焰 `fire`、冰霜 `cold`、閃電 `lightning`、腐毒 `poison`、神聖 `holy`、暗影 `shadow`、秘術 `arcane`，各有傷害數字顏色與對應的抗性屬性 `resist_*`。
  - `StatDefs.damage_factor`（`Entity.take_damage` 用）：物理 = 護甲公式 × (1 − 物理抗性)；其他 = 1 − (該屬性抗性 + 所有抗性 `resist_all`)。抗性限制在 −50%～75%（`RESIST_MIN / MAX`），秘術只吃一半的正抗性（`ARCANE_PIERCE`），弱點照算。
  - 武器：法杖改秘術、驅魔權杖改神聖、火把改火焰，其他物理。職業的「魔抗」換成「所有抗性」（照舊公式換算：魔抗 5 / 10 / 20 / 25 → 5% / 9% / 17% / 20%），「魔法傷害」改名「屬性傷害」；選角畫面的數值條「魔攻」「魔抗」改成「屬攻」「抗性」。
  - 怪物抗性寫在 `EnemyDefs` 每種怪的 `resists`（`Enemy.set_resists` 設成基礎值；守墓人變身後換成 `wolf.resists`）。遊戲裡不顯示，只寫在怪物圖鑑（2026-10-30 使用者決定）。亡者怕神聖、火焰，抗腐毒、暗影。
  - 其他傷害的屬性：燃燒、膨脹屍腐氣、守墓人噴火與殘火是火焰 / 腐毒；道具的連鎖閃電與落雷是閃電、爆炸是火焰、中毒是腐毒、鬼火是秘術。怪物其餘的攻擊是物理。
  - `entity:damaged` 在不是物理時多帶 `damage_type`，HUD 的傷害數字用該屬性的顏色（打到玩家的照舊紅色）。
  - 同一個目標 `Floaters.STACK_WINDOW`（0.2 秒）內跳的數字（屬性轉換一下兩個、冰棺分傷害）往上疊一層，疊滿 `STACK_MAX`（4）層換到左右的下一欄，不疊在一起。
  - 狀態效果（失衡、燃燒疊層、冰冷 / 凍結…）跟著羈絆做（第 5 步），這一步只有屬性與抗性。
  - **閃避率**（`dodge`，上限 75% Claude 暫定）：`Combat.apply_damage` 在格擋之後擲骰，閃掉 = 不扣血、不硬直、沒有擊退，發 `entity:dodged`（HUD 飄「閃避」）；閃避率 0 不擲骰（不消耗 `world.rng`）。
  - **尋寶**（`treasure`）：抽稀有度時，表裡最低一級以外的權重 × (1 + 尋寶)（`LootDefs.treasure_weights`，祭壇 / 石棺與武器掉落共用）。開祭壇 / 石棺用開的人的尋寶；殺怪掉武器、Boss 獎勵用全隊最高的（`World.team_treasure`，Claude 暫定：擊殺者常是投射物、追不到是誰）。尋寶 0 時權重不變、亂數序列不變。

## §2 翻滾（v0.15.0）
- 使用者決定：左 Shift；往移動方向翻（沒按方向鍵就往面對方向）；0.35 秒；前 0.2 秒無敵；1 次充能、回充 1.2 秒；**速度與距離隨移速屬性等比放大**（基礎移速 6.5 時 4 單位，移速 ×1.5 時 6 單位），時間與無敵不變。數值在 `core/config.gd` 的 `ROLL`。
- 動作層狀態 `roll`（`sim/player_states.gd`）。翻滾按鍵走 `InputCmd.BTN_ROLL` 與動作緩衝（0.25 秒）：普攻的前搖與後搖會被翻滾取消；揮下去（active）、特殊技、硬直、使用道具中先緩衝，結束後才翻。
- 無敵用 `player.dodge_timer`（`Entity.is_dodging()`）：不能被打中，投射物直接穿過；受傷後的無敵時間（`invuln_timer`）則照舊擋下投射物。
- 充能：`player.roll_charges`，上限是 `roll_charges` 屬性；回充計時用 CD key `player.roll`（乘 `roll_cooldown` 屬性），一次回 1 格，沒滿就接著回充。
- 移速只算屬性（含暫時加成），動作本身的走路減速（攻擊、硬直）與跑步倍率不算。
- **跑步**（2026-10-27 使用者，取代數字鍵 2 的疾跑）：Ctrl 切換（`InputCmd.BTN_RUN`，本步按下；`Player.running`），待機中的走路速度 × `Config.PLAYER.run_speed_mul`（1.4），沒有殘影。跳躍、翻滾、開寶箱（F 按一下不進動作層）不取消；`Player.update` 在動作層更新後，只要不在 `ready` / `roll` 就取消（普攻、特殊技、技能欄、救人、挖墳、硬直），倒地也取消。網頁版按著 Ctrl 再按 W 會被瀏覽器當成關分頁（遊戲擋不住），使用者決定維持 Ctrl（2026-10-27）。

## §3 跳躍、高度與地形（v0.16.0）
- 使用者決定：空白鍵、最高 1.5、起跳到落地 0.6 秒、只有一段跳；空中可以攻擊、用技能與道具、翻滾（空中翻滾照常下墜）；命中照實際高度計算。數值在 `core/config.gd` 的 `JUMP` 與 `HEIGHT`。
- 高度是模擬層的資料：`entity.height`（腳底）、`vz`、`ground_height`、`body_height`（身高，依 kind 查 `HEIGHT.body`）。重力 = 8 × 高度 ÷ 時間²，所有實體共用；垂直移動在 `World.step` 的碰撞分離與地形推擠之後（`Entity.integrate_vertical`，用前後速度平均，60 步 / 秒時第 18 步最高 1.5、第 36 步落地）。
- 起跳：`InputCmd.BTN_JUMP`，站在地面上隨時可跳（攻擊、翻滾中也行），硬直與倒地不行；落地沒有硬直。
- **命中高度**：目標佔 [height, height + body_height]；攻擊用 `hit.band`（Vector2 下緣、上緣）。沒給 band 時用攻擊者身體往腳底下延伸 `reach_below`（近戰、碰撞、衝鋒）。投射物是飛行高度 ± `projectile_half`，高度不重疊就從頭頂 / 腳下穿過；爆炸是地面往上 `explosion_height`；Boss 砸地打得到上下各一層高台，但目標腳底離自己腳下地面超過 `slam_height` 就打不到（`hit.max_air`，見 §9）。
- 投射物的 `height` 就是飛行高度：敵人箭矢 = 發射者腳底 + `arrow_altitude`，飛向目標的過程中線性變到「目標腳下地面 + `arrow_altitude`」（D1，打得到高台上的玩家；跳起來照樣躲得過），之後高度不變；玩家投射物 = 腳底 + `bolt_altitude`，飛出 `bolt_settle_distance` 內降到「min(發射時腳下地面, 目前位置的地面) + `bolt_altitude`」（只往下貼地，不會順著牆往上爬）。撞到比飛行高度高的石台就結束（會爆炸的照樣爆炸）。
- 碰撞分離：高度不重疊的兩個實體不互推。
- **地形**：`sim/terrain.gd`，石台資料在 `defs/map_defs.gd`（見 §9）。腳底 ≥ 頂面 − `HEIGHT.step` 才能站上去，否則石台當牆、把實體推出去；圓心在石台範圍內時地面高度就是頂面。查詢用 4 單位的格子分桶。
- 連線：快照的實體欄位要加 `height`（`PROJECT_GUIDELINES.md` 第 16 節）。

## §4 通用攻擊判定（v0.17.0）
- 設計方向：怪物**沒有碰撞傷害**，每種怪物都靠自己的招式（預備 → 判定 → 收招）攻擊。貼著怪物不會扣血。
- `sim/hitbox.gd`：玩家與怪物共用。`Hitbox.strike(world, 攻擊者, 原點, 朝向, 形狀, hit, already)` 查詢形狀內的敵對目標並套用 `Combat.apply_damage`；`already`（id 字典）讓同一招每個目標只打一次。形狀：`{shape: &"sector", range, arc}`、`{shape: &"circle", radius}`。
- hit 欄位加上 `blockable`（能不能被格擋，B5 使用）：揮砍、箭、Boss 衝鋒（v0.18.2 起）= true；Boss 砸地、爆炸、盾反 = false。可另給 `block_knockback_mul` 指定擋下時的推退比例。數值寫在資料表（`enemy_defs` 的 `swing.blockable`、`slam.blockable`、`charge.blockable`、`projectile_blockable`）。
- 每次 `strike` 都記錄到 `world.hitboxes`（每步清空，只給畫面層 F2 畫形狀，不影響模擬）。
- 骷髏戰士揮砍（使用者選「中等」）：中心距離 1.3 內且冷卻好時舉刀 0.5 秒（站定，前 50% 轉向、之後鎖定）→ 揮下 0.1 秒（前方 100°、距離 1.5 的扇形，傷害 12）→ 收招 0.5 秒；冷卻 1.2 秒從舉刀算。舉刀中被打進入受擊硬直，揮砍中斷。
- 弓手與 Boss 拿掉碰撞傷害後不補新招（使用者決定）。

## §5 劍盾格擋與招架（v0.18.0，v0.41.0 改成按住格擋 + 招架）
- Build 改版第 2 步起，格擋與招架是**木盾（副手）**的右鍵（`WeaponDefs.WEAPONS.woodShield.special`），招架傷害用主手的基礎傷害（§24）。
- 使用者決定（v0.41.0）：**按住右鍵格擋、放開就放下，沒有冷卻與時間上限**；格擋中**按左鍵招架**（冷卻 4 秒，從按下算）。數值在 `weapon_defs.gd` 的 `swordShield.special`：
  - 移速 ×0.5、會轉向瞄準點；用翻滾提前結束；格擋中有霸體（不硬直）。右鍵按住走 `InputCmd.BTN_SPECIAL_HELD`（按住類、在 `HELD_BUTTONS`），`special.hold = true` 讓 `TimedAction` 在按著時停在 active（active 長度 0：放開立刻進 0.15 秒收招）；只按一下沒按住不舉盾。
  - 招架：格擋中左鍵剛按下那一步（`Player.attack_pressed`，按住不連發）開始 `parry.window`（0.2 秒）判定。判定中擋下 = 招架成功（`player:blocked.perfect`，HUD「招架！」）→ 下一步全額盾反；判定結束都沒擋到 → 打出傷害與擊退 × `fail_damage_mul`（0.5）的盾擊。盾反後右鍵還按著就繼續格擋；判定中放開右鍵要等判定結束才放下。
  - 技能欄：格擋中左鍵那格換成「招架」（`SkillBar._parry_slot`）並顯示招架冷卻。
  - 擋得住：`blockable` 的攻擊（揮砍、箭），來向在正前方合計 120°（左右各 60°；v0.23.0 使用者決定，原本 75°）內。格擋中腳下前方顯示金色扇形（`WorldView` 的 BlockFan，半徑 2.2、角度同 `block_arc`）。擋下時不扣血、自己被推退 30% 擊退，發出 `player:blocked` 與音效；箭會消失。
  - Boss 衝鋒（v0.18.2 使用者決定）：擋得住、不扣血，但推退 100%（`charge.block_knockback_mul`）；同一次衝鋒擋下後不再判定。
  - 擋不住：砸地、爆炸（不是 blockable），或來自側面 / 背後。
  - 盾反範圍：前方 180°、距離 3.5（v0.23.0 使用者決定，原本 120° / 2.5）；傷害 25 × 攻擊力、大擊退、重擊顯示（招架失敗的減半盾擊不算重擊）。`fx:parry` 帶 facing 與 arc，畫面閃一下實際打得到的扇形。
  - 測試裡按住格擋要每步帶 `BTN_SPECIAL_HELD`（`player_checks.gd` 的 `HOLD` / `PRESS_HOLD`）。
- 實作：`ShieldBlock` 行為記錄 `player.block_time`（格擋開始後秒數，< 0 = 沒在格擋）；`Combat.apply_damage` 對 blockable 的攻擊先呼叫 `target.try_block(來源位置, hit)`；盾反延到下一步執行（`pending_parry`），避免在怪物出招的途中改動怪物狀態。

## §6 物品資料（v0.19.0）
- 使用者決定：資料放程式資料表 `defs/item_defs.gd`（`ItemDefs.ITEMS`）。武器與道具共用一種格式：`kind`（`item` / `weapon`）、`name`、`rarity`、`shape`、`desc`、`effects`；道具另有強度分數 `power`，武器另有 `weapon`（對應 `WeaponDefs`，武器數值仍在那邊）。
- 稀有度 `RARITIES`（名稱、顏色、格數 `cells`）、占格形狀 `SHAPES`（格子座標，左上為 (0, 0)、上下左右相連）、背包 `BAG_SIZE` 8×6。**道具格數看稀有度**（白 1、綠 2、藍 3、紫橘 4，Build 改版第 5 步，§27），power 只當平衡參考。
- 效果四種寫法：
  - 屬性 `{stat, op, value}`：放進身上就生效。
  - 條件屬性 `{when, stat, op, value, …}`：條件見 `CONDITIONS`。
  - 觸發 `{on, do, chance?, …}`：時機見 `TRIGGERS`，動作見 `ACTIONS`。
  - 能力 `{ability, …}`：見 `ABILITIES`。
  - 各表的 `params` 是必填參數，`check.gd` 會檢查。新增條件、觸發、動作或能力時先加進表。
- 屬性效果走 `ItemDefs.stat_mods`；條件、觸發、能力在 `sim/item_effects.gd`（第一批 §16、第二批 §20）。
- 放進身上：`Player.add_item(id)` 建立實例 `{uid, id}`，以 `uid`（`item_N`）為屬性來源；`remove_item(uid)`、`clear_items()` 拿掉。武器道具直接 `equip_weapon`，不放進 `items`。還沒有背包介面，放進來就生效。
- 除錯：F4 依清單順序放入下一個道具，F5 清空；`--items=id,id`。

## §7 特效（v0.20.0）
- 畫面層 `view/effects.gd`（`WorldView.effects`）照搬網頁版 `Effects.js`：方塊粒子（`burst`、`mote`）、揮砍弧光（`slash`）、衝擊環（`ring`）、預警圈（`telegraph`，只給玩家方的聖光圈與道具用；怪物攻擊不畫圈，見設計方向）。Boss 砸地的地板裂紋在 `enemy_animator.gd`（`slam_crack`）；一段時間內持續冒粒子的事件特效（瞬移前的紫煙、挖墳點的泥土）用 `Effects._add_emitter`。
- **一次性特效走事件**：模擬層發 `fx:*`（`PROJECT_GUIDELINES.md` 第 9 節的表），payload 只放位置（`pos` Vector2、`height`）、顏色與尺寸，不放實體參照。命中、死亡、狂暴直接用既有事件。新增特效事件時：模擬層 emit → `Effects.HANDLERS` 加處理函式 → 列進`PROJECT_GUIDELINES.md` 第 9 節；`check.gd` 會檢查三者一致。
- **持續性粒子由畫面層依狀態產生**（投射物拖尾、蓄力、爬出、拉弓、衝鋒、暈眩、召喚、疾跑殘影），不發事件，連線時不佔頻寬。網頁版「每步機率 p」換算成每秒 p × 60 顆，小數累積到下一幀（`_count`），和幀率無關。
- 上限：粒子 `MAX_PARTICLES` 600（一個 MultiMesh），弧光與環 `MAX_TRANSIENTS` 64。開場先畫一次透明的粒子與環來預先編譯著色器。暫停時停住、`game:restart` 時清空。

## §8 多人連線（v0.21.0，C1~C4）
- **使用者決定**（2026-10-23）：區網 ENet、1~4 人合作、房主即權威；誤傷開啟；敵人數量不變、血量每多 1 人 +50%；只能開局前加入（中途加入先不開放）；移動 / 翻滾 / 跳躍本機預測，攻擊與技能的動作、音效本機立即播，傷害一律由房主判定；倒下假死 10 秒、隊友按住 F 累積 5 秒救起、救起 30% 血、全員倒下就輸。數值在 `Config.NET`、`Config.REVIVE`。
- **三種模式**（`main.gd`）：單機 = 沒有連線的房主（同一條程式路徑）；房主跑唯一的 `World`，`NetHost` 收各玩家輸入排隊（每步取一筆，排超過 `input_queue_max` 筆就把最舊的併進下一筆，本步按下的按鈕保留）；客戶端不跑 `World.step()`，`NetClient` 用快照維護鏡像 `World`（`is_authority = false`）。
- **傳輸**（`net/net_session.gd`）：玩家在主選單選連線方式（v0.40.0）。IP 連線 = ENet（只有桌面版）；房號連線 = WebRTC（v0.36.0，`WebRTCMultiplayerPeer`，頻道 1 = unreliable；`net/peerjs_signaling.gd` 經 PeerJS 公開配對伺服器用 4 碼房號交換 OFFER / ANSWER / CANDIDATE，連上後就不經過伺服器；ICE 用 Google STUN + PeerJS 公開 TURN）。網頁版用瀏覽器內建的 WebRTC，桌面版用 `addons/webrtc_native`（Godot 官方 webrtc-native 1.2.2，repo 只放 Windows / Linux x86_64；macOS 的 `.framework` 不進版控，Mac 開發機照 `docs/新電腦設定.md` 5.2 自己下載），所以房號連線桌面版與網頁版能互連。輸入（客戶端每步送最近 `input_redundancy` 筆）與快照（房主每 3 步）走 unreliable；事件每步一包走 reliable（`[run_id, tick, events]`）。RPC 的節點路徑以 `main` 為根（`get_tree().set_multiplayer(…, main 的路徑)`），直接執行與在 `capture.tscn` 裡執行的程序能互連。`--net-latency` / `--net-loss` 模擬延遲與掉包。
- **快照**（`net/net_codec.gd`，v0.35.0 改成二進位 + 只送附近）：`[run_id, tick, ack, 世界狀態, 實體位元組 PackedByteArray, 有 extra 的實體的 extra]`。每個實體：id（u32）、種類（u8，`KINDS` 表）、旗標（u8）、x、z、[高度]、朝向、最大生命、[生命]（float32）、[速度、閃白 / 無敵]（half）、動畫（欄位名稱用 `ANIM_KEYS` 索引、常見名稱用 `NAMES` 索引、浮點數 double）。旗標標示的欄位是預設值時整個不送（滿血、靜止、計時器 0、高度 0；普通怪沒有 extra），無損。每個實體只編碼一次（`encode_entities`），`NetHost.snapshots` 再依玩家挑出 `NET.interest_radius`（24 = 視野 18 + 緩衝）內的實體，玩家與 Boss 一律送；別人的背包（`P_INV`）不送。客戶端照舊「快照有就建、沒有就移除」。量測（地圖 A 怪群 + 4 人）：一般每份 1.7~3.8 KB、身邊 120 隻時 7.0 KB（v0.34 每份送全部約 28 KB）；檢查上限 4.5 KB / 8 KB（網頁 WebRTC 單則約 16 KB；4 KB → 4.5 KB 見 CHANGELOG）。客戶端用同樣的類別建立鏡像實體（`Player`、`Spawner.create`、`Projectile`），畫面層不用分辨單機或連線。
- **其他實體**：畫面時間 = 估計的房主 tick（最新快照 + 收到後經過的步數）− `interp_delay_ticks`（6 步 = 100 ms），在前後兩筆快照之間補間（位置、高度、朝向；動畫的狀態相同時數值欄位也補間）；連續掉包追上最新快照時，沿速度最多往前推 `max_extrapolate_ticks` 步。事件也依 tick 延到畫面時間才播，和畫面對得上。
- **自己的角色**：`World.step_predicted` 只推進自己（同 `step()` 的順序，但不扣血、不產生投射物，投射物等快照）。每筆快照帶 `ack`（房主最後套用的該玩家輸入編號），誤差 = 房主在 ack 時的位置 − 本機當時預測的位置，加到目前位置與之後的預測紀錄（不倒帶重播，狀態機與計時器不用存檔）；差超過 `snap_distance` 直接跳過去。血量、倒地 / 死亡、盾反、武器以房主最新快照為準；倒地 / 死亡時不預測，位置直接用房主的。被房主判定打中時本機立刻進入受擊硬直（`Player.net_hurt`）。
- **事件去重**：World 更新某位玩家時，事件標上 `actor`（peer id）；`Combat.apply_damage` 與盾反期間清掉（不是預測得到的）。客戶端丟掉 `actor` 是自己的房主事件。
- **打中回饋預測與延遲補償**（v0.38.0，試玩回報「打怪有 0.幾秒延遲」：量到客戶端看到命中 = 出招時間 + 來回延遲 + 100 ms）：
  - 客戶端預測自己的出招時，`Combat.apply_damage` 不扣血，但目標的高度範圍對得上（對方沒在格擋）就發 `hit:predicted`：畫面層馬上噴火花（`Effects`）、播命中音效（`Sound`），`NetClient` 讓目標閃白（`_flash`，蓋過快照的閃白）。
  - 房主的同一下 `entity:damaged`（source 是自己、`predicted_hit_window` 步內有預測紀錄）被標 `predicted = true`：只顯示傷害數字、扣血照房主，火花與音效不再播；順序照房主，照樣排到畫面時間（傷害數字仍晚「延遲 + 100 ms」）。
  - 延遲補償：`InputCmd.view_tick` = 客戶端這一步的畫面時間（`render_tick`）。房主（`NetHost` 開 `World.rewind_enabled`）每步結束記敵人與玩家的位置（最多 `rewind_max_ticks` = 30 步），更新該玩家時 `rewind_tick = view_tick`，`Hitbox.query` 先把目標移到那時的位置再判定、判定完放回去。只補償近戰判定（投射物照房主的時間飛）；怪物打玩家沒有補償。
  - 量測（`tests/net_checks.gd` 的 `check_hit_prediction`）：單程 100 ms 時打中回饋從第 24 步（400 ms）變成第 6 步（100 ms，同單機）；側移的怪「客戶端看到打中、房主也判定打中」沒補償 11 / 17、補償後 17 / 17。
- **CD**：每位玩家的 CD 實際存在 `Player.cd(key)`（`key@peer_id`）；事件與 HUD 仍用 `player.special` 這類名稱。
- **誤傷**：`Combat.hostiles_of(world, team, source_id)` 在 `Config.NET.friendly_fire` 時把其他玩家也當目標，但不含出招者自己（投射物用發射者 id）。
- **倒下與救援**（`Player.die` / `_go_down` / `revive`、`World._update_downed`、動作層 `revive` 狀態）：多人時生命歸零先倒地（`is_downed`，移動層 `downed`，不能被打、不被怪追、不接受輸入）；隊友按住 F（`InputCmd.BTN_INTERACT`）、中心距離 ≤ `REVIVE.range` 就進入 `revive` 動作（不能移動 / 攻擊 / 跳），倒地者救援進度 +1/秒、倒數暫停；放開時進度每秒 −`decay_rate`（Claude 暫定和累積同速）、倒數照走；沒有站著的玩家時所有倒地者直接死亡並發 `game:defeat`。單機倒下 = 死亡（和以前一樣）。
- **只有單機才有**：F3~F5 除錯鍵（直接改模擬狀態）、暫停（連線時 Esc 只開選單）、失去焦點自動暫停。F1 切武器改走 `InputCmd.BTN_SWAP_WEAPON`，連線時也能用。
- **斷線**：房主那邊有人斷線就移除他的角色；客戶端和房主斷線就回到單機。網頁版（v0.36.0 起）連線選單改成房號；房主切換分頁時瀏覽器停掉畫面更新，所有人都會停住（大廳有提示）。

- **網頁版 WebRTC 接收緩衝區**（2026-10-27）：`project.godot` 的 `network/limits/webrtc/max_channel_in_buffer_kb = 2048`（預設 64）。遊戲每幀把收到的資料讀走，但任一邊單一幀卡超過約 1 秒（弱電腦、第一次編譯著色器），64 KB 就被快照塞滿，引擎丟資料（`webrtc_data_channel_js.cpp` 的 `Buffer full! Dropping data.`，可靠通道也丟）並狂刷錯誤，2026-10-27 三人試玩房主因此當掉、隊友卡住。持續低幀率不會塞（每幀都讀）。檢查「桌面版 WebRTC」擋 < 1024。
- **本機網頁版多人測試 / 網址連線參數**（2026-10-27 使用者同意開放）：`WEB_URL_ARGS` 開放 `host` / `join` / `room` / `net-autostart`，`?host&room&net-autostart=N` 開房（印出 `net room=房號`）、`?join=房號&room` 加入；用途是多人自動測試，之後可做邀請連結。原本為了「朋友開網站不受影響」不開放，評估後風險小（加入的人隨時能離開、連線本來就互相看得到 IP；`?seconds` 早就開放）。測試要用多個關掉背景降速的瀏覽器視窗（同一瀏覽器的背景分頁會被降速，反而造成假的 Buffer full）；本機連本機走區網位址，**測不到 NAT / TURN**。
## §9 地圖與怪物尋路（v0.22.0，D1）
- **地圖資料**：`defs/map_defs.gd` 的 `MAPS`。地圖座標左上角 (0, 0)、x 往右、y 往下（= 世界 X、Z），世界座標 = 地圖座標 − `origin`（地圖中央在世界原點）；畫面是等距視角，所以地圖在畫面上轉 45°（菱形）。每張圖有 `size`、`spawn`（玩家出生點）、`dig`（挖墳點 = 出口，D6 使用）、`spawn_rule`、`blocks`（[x, y, 寬, 深, 頂面, 種類]）、`tomb_rows`（一排排墓碑）。
- **石台種類**：`wall`（牆 / 陵墓，頂面 3.0，跳不上去）、`tomb`（墓碑 1.2 × 0.5、高 1.3：擋箭與魔彈，玩家跳得上去）、`platform`（可以站的高台，0.5 / 1.0）。
- **地圖**：`graveyard_a`（A 環形墓園，96 × 96，使用者選定；遊戲用 `Config.WORLD.default_map`）、`test_arena`（舊的 32 × 32 測試場地，`check.gd` 大部分檢查用）。B、C、D 草圖在 `mockups/graveyard_map.html`，之後做成資料並隨機抽（使用者決定）；屆時房主要把地圖編號傳給客戶端（目前兩邊都用 default_map）。
- `World` 建立時載入地圖（`World.new(map_id)`、`load_map`）：`half_extents`（場地一半大小，限制實體與投射物）、`terrain`、`nav`、`spawn_point`；玩家出生在 `spawn_point`。
- **沒有安全區**（使用者決定）：玩家去得了的地方怪物都去得了，怪物只是比玩家多花一點時間上去。
  - 尋路（`sim/nav.gd`）：1 單位的格子，牆與墓碑往外擴 margin 的格子是障礙，高台可走；路徑用引擎內建的 `AStarGrid2D`（八方向、不切牆角），再拉直看得到的點。只在權威端算。依體型兩張：`World.nav`（小怪，`NAV.margin` 0.6 = 半徑 0.45 + 0.15）、`World.nav_large`（半徑 > `large_radius` 的 Boss，`margin_large` 1.15），用 `World.nav_for(radius)` 取。
  - 「看得到、直接走」是精確的線段判斷（`Terrain.segment_blocked`：線段與「牆 / 墓碑往外擴 margin」的長方形相交；起點已貼牆時往外走不算擋住）。v0.22.0 用格子取樣，直線會擦到牆角，怪物看起來一直撞牆（繞北門時 154 步被牆擋住變慢，v0.23.0 為 0 步）。
  - 怪物每 `NAV.repath_interval` 秒判斷一次：看得到就直接走向玩家（和以前一樣），否則照路徑點走（`Enemy.steer_point`）。
  - 離目標超過 `far_distance`（18 = 視野範圍）的小怪改成每 `repath_interval_far`（1 秒）判斷一次，依 id 錯開 0~7 步；走進 18 以內的那一步立刻重新判斷（弓手的 `line_of_fire` 也跟著更新，進射程不會用遠處的舊判斷）。Boss 照舊每 0.25 秒（衝鋒要看 `has_direct_path`）。效能用，`check.gd` 的「遠的小怪降低重新判斷路線的頻率」檢查。
  - 起跳偵測先用 `Terrain.may_rise` 排除：分桶記著桶內石台的頂面高度，前方的地面不可能高出 step ~ `climb_height` 時不逐一比對石台；結果和直接算 `ground_at` 相同（`check.gd` 兩張地圖密集取點比對）。
  - 跳上高台（`Enemy._update_jump`）：站在地上往前走、前方 `jump_lookahead` 的地面比腳下高出 `step` ~ `climb_height`（1.1）就先蹲 `jump_windup`（0.25 秒）再用玩家的起跳速度跳；空中往起跳方向至少 `jump_air_speed`（4.0），身體整個越過邊緣才落地（Boss 半徑 1.0、移速 2.2，v0.22.0 會掉回去）。1.3 的墓碑太高不跳，站在下面揮砍 / 射擊打得到。
  - Boss 衝鋒（v0.23.0）：前方是高低差 ≤ `climb_height` 的高台就在衝鋒途中直接跳上去、不停；更高的牆與墓碑、場地邊緣才撞停暈眩。衝鋒中不做一般的蹲跳。
  - Boss 砸地（v0.23.0）：範圍內站在任何地面上（含旁邊的高台）的目標都打得到；`hit.max_air` = `slam_height`，腳底離自己腳下地面超過 0.5（跳起來）才躲得過。
  - 弓手：看不到玩家或箭會撞到石台時先繞路靠近、不射擊；箭瞄準玩家腳下地面的高度。
  - 地圖規則（`check.gd` 檢查）：所有可走格連成一片、相鄰可走格高低差 ≤ `climb_height`、牆比最高的地面高出跳躍高度 + 0.3 以上。
- **生成**（`spawn_rule`）：`arena` 同以前（整個場地隨機、Boss 在玩家對面）；`around_player`（大地圖）小怪生在離玩家 `min_distance_from_player` ~ `max_distance_from_player`（8 ~ 18）、可走而且走得到玩家的格子；Boss 往地圖中央方向、離玩家 `boss_distance`；Boss 召喚的小怪落在障礙格時移到最近的空地。
- 畫面：`ArenaView.create_blocks` 把所有石台合併成一個網格（每個石台 5 面、頂點色依種類），地圖上有上百個石台也只畫 1 次。

## §10 角色視野（v0.24.0，D2）
- 使用者決定：前方 120°、18 單位；身邊 4 單位不管方向都看得到；牆（`wall` 種類）擋視線，墓碑與高台不擋；視野外的地面變暗。數值在 `Config.VISION`。
- **只影響畫面**：模擬照常進行（看不到的怪照樣會打你），沒有網路同步的改動；每個程序只依自己的本機玩家（`WorldView.local_peer`，`main.gd` 換 World 時設定）決定畫什麼。
- 判斷在 `sim/vision.gd`（純函式）：`Vision.point_visible(world, 看的人, 位置, 目標半徑)`：距離 ≤ 18（加目標半徑）、在身邊 4 單位內或扇形內（身體邊緣進入就算）、而且視線不被牆擋（`Terrain.sight_blocked`，身邊一圈也會被牆擋）。`Vision.entity_visible`：自己、自己發出的投射物一律看得到；怪物、隊友、別人的投射物照位置判斷；看的人不存在或已陣亡時全部看得到。
- 看不到時不畫：怪物與隊友的模型（Boss 地面預警是模型的子節點，一起隱藏）、別人的投射物、位置在視野外的 `fx:*` 特效事件、看不到的實體的持續性粒子（`Effects.hidden_ids`）、HUD 的傷害數字、隊友名牌。音效照常播（聽得到）。之後的寶箱等可互動物件也要接 `Vision`。
- 變暗：`WorldView` 的全畫面四邊形著色器，從深度貼圖還原每個像素的世界位置，視野內蓋 `inner_darkness`（0.1）、視野外蓋 `darkness`（0.3）的黑色，邊緣漸層 `edge`（0.3，2026-10-26 使用者要邊界清楚；v0.27.0 曾改成 3.0），前方遠端的弧形 `range_edge`（0.8 = 側邊 + 0.5）、身邊一圈 `near_edge`（1.0，背後柔一點）；v0.27.0 使用者要內外亮度差小一點（原本只有外面 0.5）。牆擋住的區域不畫暗（只隱藏牆後的東西）。Compatibility（網頁版）用 `CURRENT_RENDERER` 換深度的換算方式，網頁版還沒實測。
- **判斷用的半徑**（2026-10-26）：`Vision.view_radius`：寶箱、地上的道具看中心（露一角不出現），怪物、玩家、投射物看身體邊緣。
- **淡入淡出**（2026-10-26 使用者選 Project Zomboid 的做法）：`WorldView._sync_fade` 每個模型一個顯示程度 0~1，每幀往目標靠近（進入視野 `fade_in`、離開 `fade_out` 都是 0.2 秒，使用者試玩後決定），0 就不畫；淡出中照常擺位置與姿勢。剛建立的模型、走進出口的玩家、本機角色陣亡時直接到位。頭頂血條、名牌、傷害數字、持續性粒子仍看 `hidden_ids`，離開視野立刻消失。
  - 作法在 `view/fade.gd`：淡入淡出中網格換成半透明的材質，完全顯示時換回原本的（原本的材質不改）。每個半透明材質兩次繪製：先一次只寫深度，再畫半透明的顏色（`next_pass`），零件不互相透出來。不用 Godot 的 `TRANSPARENCY_ALPHA_DEPTH_PRE_PASS`：它只在 alpha ≥ 0.99 時寫深度，重疊的零件會一塊塊透出來；不用 `GeometryInstance3D.transparency`：網頁版（Compatibility）不支援。
  - 半透明材質全遊戲共用一份快取：key = 原本材質的外觀（顏色、著色方式、自發光量化到 0.1）+ 透明程度（`Fade.LEVELS` 8 階）。開場預熱用 `Fade.prepare` 把每種模型每一階都建好，遊戲中轉身只換網格指向的材質，不新建、不切換材質（網頁版每次轉身新建 / 切換材質會卡）。代價：淡入淡出中受擊閃白、狀態染色停在開始那一刻；透明度 8 階跳變。燈光亮度跟著階數乘。
  - 淡入淡出中不畫牆後剪影，完成後接回剪影。
  - **影子跟著淡**（2026-10-27 使用者要求）：原本淡入淡出中不投影（半透明材質不投影），影子在淡入結束時才跳出來、淡出一開始就消失。影子圖沒有半透明，改成第三次繪製 `Fade.SHADOW_SHADER`（接在半透明材質的 `next_pass`）：一般畫面全部 `discard`，畫影子時（`IN_SHADOW_PASS`）依 `coverage` = 階 / `LEVELS` 用 4×4 Bayer 抖動丟掉像素。只跟階數有關，`_shadow_cache` 共用 7 份。網頁版著色器程式 161 → 175（M5 預熱 2.9~3.1 → 2.7~3.2 秒，看不出差別；Windows D3D11 編譯慢的那台還沒量）。
- **觀戰**（2026-10-26 使用者要求）：多人時本機真的陣亡（倒地假死不算）後看站著、沒走進出口的隊友（`WorldView.spectate_target`，依 peer id 排序）：自動看第一位，滑鼠左鍵 / A 換上一位、右鍵 / D 換下一位（同移動鍵，死亡後沒有其他用途）（循環），看的人死了或走進出口就換，沒人可看就不觀戰；被救起、冤魂復活後立刻回到自己。
  - 用隊友的視野（使用者決定）：`WorldView.viewer()` 回傳被觀戰的隊友，扇形、牆擋視線、變暗遮罩、`fx:*` 過濾都以他為準；場上文字與名牌（`WorldLabels` / `PlayerTags` 的 `view_peer`）也是；鏡頭跟著他（`main._player_view_position`）。HUD 上方中央顯示「觀戰中：P2　滑鼠左右鍵或 A / D 切換」。
  - 連線：`InputCmd.spectate` 帶著看的人送給房主，`NetHost.viewer_of` 在該玩家陣亡時改以那位隊友為中心挑快照（`interest_radius`），遠處的隊友周圍才有東西。
  - 挖墳時視野跟著滑鼠（2026-10-26 使用者提出）：挖墳不鎖朝向（v0.38.0），視野遮罩照模型朝向，本來就會跟著轉；`check.gd` 補檢查防退步。
  - 變暗遮罩的 `render_priority` 是最低（最先畫）：半透明的東西不在深度貼圖裡，遮罩會讀到它們後面的地面，淡入淡出中的怪物被切成上下兩半。代價：所有半透明的東西（淡入淡出中的模型、冤魂、道具光柱、格擋扇形、部分特效）都不被視野壓暗（視野內差 10%）。

## §12 武器掉落、裝備欄與合成（v0.26.0，D4）
- **Build 改版第 2 步起，2 格裝備欄與 X / 滾輪切換改成主手＋副手（§24）**；「裝備欄」讀成主手 / 副手。**第 8 步起詞條改成跟羈絆有關、合成要在鍛造祭壇（§30）**，下面的 10 種詞條與「在背包裡拖就能合」已不適用。
- 資料在 `defs/weapon_drop_defs.gd`：`DROP_CHANCE`（小怪 4%、Boss 100%）、`RARITY_WEIGHTS`（小怪 白 60 / 綠 25 / 藍 12 / 紫 3、Boss 藍 60 / 紫 30 / 橘 10）、`AFFIXES`（10 種詞條，Claude 擬、暫定）。詞條數 = 稀有度序號（白 0 ~ 橘 4），同一把不重複（部分洗牌，用 `world.rng`）。
- **武器實例**：`{ uid, base, rarity, affixes }`；uid 由 `World.new_weapon_uid()` 產生（全場唯一，`w1`、`w2`…，`reset` 歸零）。快照格式 `WeaponDropDefs.to_array / from_array`。
- **裝備欄**：`Player.weapon_slots`（2 格）與 `active_slot`。只有手上那把的詞條生效（屬性來源 `&"weapon"`，`Loadout.apply_active_weapon`）；換了另一把（uid 不同）才重設連段與動作。`equip_weapon(id)` 把手上這格換成新的白色武器（開場、`--weapon`、測試）。`show_weapon` 只換招式資料（客戶端畫別人用）。
- **切換**：`InputCmd.BTN_SWAP_WEAPON`（X、滑鼠滾輪，v0.31.0 起取代 Q；取代 F1 除錯切換）→ `swap_weapon` 換到另一格，另一格是空的不換。客戶端在房主處理完自己最後一次切換前保留本機預測的 `active_slot`。
- **掉落**：`World.on_enemy_died` 依機率在屍體位置 `drop_weapon`（`ItemPickup` 帶 `weapon`）；多人時房主只產生一個實體，先撿先得。發 `weapon:dropped`。
- **撿起**（F，同 D3）：`add_weapon`：空的裝備欄 → 背包（`find_spot`，條目帶 `weapon`、不算生效道具）→ 都放不下發 `inventory:full`。從腳邊拖進背包（`OP_PICKUP`）時直接放到那一格，不放空的裝備欄。
- **背包操作**（`InputCmd.inv_ops`）：`OP_MOVE` 武器可以從裝備欄搬進背包、`OP_DROP` 丟到地上（手上至少留一把）；`OP_EQUIP [uid, slot]` 放進裝備欄（從另一格來就互換，從背包來時原本那把回背包、放不下就不換）；`OP_MERGE [a, b]` 把 a 拖到 b 上：同種、同稀有度、不是橘色才行，b 的位置換成高一級、詞條重抽的新武器（uid 沿用 b），a 消失；手上唯一的一把拖到背包的武器上時，結果留在裝備欄。不能合成發 `weapon:merge_denied`。
- **快照**：玩家 extra 加 `P_SLOTS`（兩格武器）、`P_ACTIVE`；背包條目第 6 欄是武器；地上道具 extra 第 2 欄是武器。
- **介面**：背包面板上方 2 格裝備欄（使用中金框），拖到武器上顯示「合成」、拖到裝備欄裝上；下方說明顯示武器詞條（在背包裡標「不生效」）。左上「武器：稀有度 名稱（Q：另一把）」，文字用稀有度顏色。地上的武器是斜放的發光長條。

## §13 試玩回饋調整（v0.27.0）
- **二段跳**：道具能力 `double_jump`（雙躍之靴）接上：`Player.air_jumps()`（背包裡有就 1 次），空中再按跳躍從目前高度往上跳一次（同第一段的起跳速度），落地重置。`ItemDefs.is_implemented` 把 double_jump 算進已實作。

## §14 成群怪物與怪物稀有度（v0.28.0，D5）
- 資料在 `defs/monster_rarity_defs.gd`：`RARITIES`（普通 / 魔法 / 稀有的生命、傷害、體型倍率、詞條數、顏色）、`AFFIXES`（8 種）、`PACKS`（怪群規則）、稀有怪名字表。
- **稀有度**：`Enemy.set_rarity(rarity, affixes, name)` 設欄位與體型（半徑、身高 × scale）；權威端再 `apply_rarity_stats()`：屬性來源 `&"rarity"`（最大生命、攻擊力相乘，乘在 `&"wave"` 之上）、`&"affixes"`（詞條的 mods）、`&"affix_regen"`（再生 = 最大生命 × 2% 的 hp_regen）。`Spawner.roll_rarity` 抽詞條（不重複、`world.rng`）與名字；普通不抽、不耗亂數。
- **詞條行為**（`Enemy`）：吸血在 `Combat._apply_damage` 命中後呼叫 `on_dealt_damage`；狂暴在 `_update_affixes` 觸發一次，`action_speed` 1.4 乘在狀態機時間上（`fsm.update(dt × action_speed)`），冷卻用 `cd_time()` 除以它，移速來源 `&"frenzy"`；死亡爆炸不畫預警圈（畫面上屍體一下一下脹大、閃白、冒出詞條顏色的氣體：`EnemyAnimator.volatile_swell / volatile_flash`），`Dead` 狀態 delay 秒後 `Hitbox.strike`（擋不住、通關後不炸）；召喚醒著時每 interval 秒用 `spawner.spawn_at` 叫骷髏戰士（`summoner_id`，同時最多 max_alive）。
- **怪群**：地圖資料 `"packs": true` 且 `World.spawn_packs`（`--no-spawn` 與 check.gd 預設關）時，`World.reset` 呼叫 `Spawner.spawn_packs`：群中心離出生點 ≥ 15、可走且連通、群距 ≥ 10；成員散在 3.5 內、彼此 ≥ 1.0。成員以 `mul.dormant = true` 出生（狀態 `dormant`，不播爬出），`World.packs` 記 `{ center, ids, awake }`。`World._update_packs`（玩家更新後、敵人更新前）任一可被當目標的玩家離中心 ≤ 12 就 `wake_pack`；成員被打（`_on_damaged`）也整群醒來。醒來同一步就切到主狀態。
- **波次**：只有 `wave_member`（`_spawn_from_queue` 生的）擋下一波；怪群、召喚的不算。通關時休眠的怪群不會一起倒下。
- **快照**：敵人 extra 第 2~4 欄是稀有度、詞條（字串陣列）、名字，普通怪不送；客戶端只 `set_rarity`（外觀），數值以快照為準。
- **畫面**：魔法 / 稀有怪腳下發光環、身上 OmniLight（範圍 3、亮度 1.5），稀有怪模型 ×1.2；`WorldLabels` 頭上畫詞條（稀有怪多一行名字）。
- **效能做法**（200 隻怪的目標：RTX 3070 144 FPS、內顯 60 FPS）：
  - 骷髏戰士 / 弓手用 `view/skinned_rig.gd`（`DarkFantasy.skinned_character`）：同種的零件模板合成一個蒙皮網格（頂點色、依「自發光、投影」分組，最多 2 個網格），9 根骨頭 = Rig 的 anchors，綁定姿勢為單位矩陣（頂點存在各自關節的座標系）。關節是只存數值的 `Joint`（介面同 Node3D 的 position / rotation / scale），動畫寫完後 `flush()` 只把有變的骨頭寫進 Skeleton3D。Boss 與玩家仍用 `Rig`。
  - 模擬層：`SimPhysics.separate` 用 Packed 陣列與攤平的鏈結串列格子；`World.player_list` 取代每次 `players.values()`；`Enemy.cd()` 快取字串；`Enemy.anim` 沿用同一個 Dictionary；位置與上次算地形時相同、站在地上的實體跳過推出石台與落地（`Entity.terrain_checked_pos`）。
  - 畫面層：視野結果只在 tick 或觀看者改變時重算，牆擋視線每隻每 `LOS_INTERVAL`（3）步重算（剛進入扇形立刻算）；看不到的節點不更新；敵人四肢動畫每秒最多 60 次；節點位置與朝向一次寫入 transform；閃白沒變不改材質；太陽陰影 `SHADOW_ORTHOGONAL`、最遠 70。
  - 量測：`main.gd --horde=N --perf`（離屏截圖場景，見 `CLAUDE.md` 1.8）與 `stress_test/profile_horde.gd`（headless，模擬層各段）。

## §15 挖墳事件、難度與換層（v0.29.0，D6）
- 資料在 `defs/event_defs.gd`（`DIG`、`ERUPT`、`VOTE`、`DIFFICULTY`、`SPAWN`、`GHOST`），邏輯在 `sim/dig_event.gd`（`World.event`）。只有地圖資料 `"dig_event": true` 的地圖有（`DigEvent.enabled`）；這種地圖的 `Spawner.update` 不跑波次，測試場地照舊。
- **挖墳**：玩家動作層 `dig`（`Ready` 在按住 F、附近沒有倒地隊友、`event.can_dig` 時進入）：移速 0、不能跳，**朝向照樣跟著滑鼠**（按住互動的吟唱動作——救援、挖墳、以後新增的——都不鎖轉向）；`_on_damaged` 與 `stun` 不打斷；屬性來源 `&"digging"` 讓擊退 ×0，質量暫時 `DIG_MASS`（1000，碰撞推不動）。`DigEvent.update`（`World.step` 在 `spawner.update` 之後）：有人 `is_digging()` 且狀態 idle → `_start`（`event:started`，怪潮與噴怪同時開始）；active 時進度 += 挖的速度合計 × dt ÷ `dig_total`（`DIG.time` × 沒死的人數，倒地的也算），沒人挖每秒 −`DIG.decay`（0 = 不掉）；滿了 → `_open`（`event:exit_open`）。
- **Boss 巡邏**（2026-10-28）：每一層的第一步 `DigEvent.spawn_boss` 在挖墳點放 Boss（`initial_state = &"patrol"`，`--no-spawn` 不放；第一步才放是因為 `spawner.finished` 在 `reset` 之後才設）。`Boss.Patrol` 在 `patrol_rect`（地圖資料 `boss_room` [x, y, 寬, 深]）裡挑走得到的點、`patrol.speed_mul` 慢慢走、到了停 `patrol.pause` 秒；`sees_player`：前方 `sight_arc` 扇形 `sight_radius` 內或任何方向 `notice_radius` 內、`nav.has_los` 沒被牆擋 → `aggro()`（重新開始招式冷卻 `first_cooldowns`、切到 `chase`、發 `boss:aggro`），被打也 aggro；之後照一般追擊、不限範圍。巡邏中 HUD 不顯示 Boss 血條。
- **怪潮**：事件 active 時每 `spawn_interval(難度)` 秒在隨機一位可被當目標的玩家周圍（`Spawner._around_player`）冒 `group_size` 隻（`wave_member = true`，同時最多 `max_alive`），稀有度 `EventDefs.roll_rarity`；第一批在 `interval_start` 秒後。
- **挖墳點噴怪**（2026-10-28）：`erupt_timer` 從 `ERUPT.interval` 倒數，剩 `warning` 秒時發 `fx:erupt_warn`（墳土隆起、裂開、冒出白骨手，不畫圈），到 0 時進度 + `ERUPT.progress`、發 `event:erupted` 與 `camera:shake`，噴 `erupt_count(難度 − 基礎難度, 人數)` 隻（和怪潮共用 `max_alive`）：`spawn_at(..., {difficulty = 目前難度 + per_floor, initial_state = &"launch"})` + `Enemy.launch_to(落點, flight_time)`。落點是挖墳點 `land_distance` 外最近的可走格；`Enemy.Launch` 狀態每步照固定水平速度走、`vz = 重力 × flight_time ÷ 2`（最高點 = 重力 × flight_time² ÷ 8，現在 4.17），空中不行動、受擊不硬直，落地（過了一半時間且 `is_grounded`）切到 `main_state`。畫面動畫 `launch`（雙手往上甩）。`--no-spawn` 只加進度、墳土不隆起、不冒怪。
- **難度** = `World.base_difficulty` + 事件秒數 × `per_second` × 選的難度倍率（`World.difficulty()`）；事件秒數只在 active 時累加，挖完就停。`Spawner.spawn_at` 在挖墳地圖用 `EventDefs.difficulty_mul`（所有怪，含 Boss；`extra.difficulty` 可指定）。
- **挖完與換層**（2026-10-28）：`open` 後不再生怪、難度不漲，場上的怪留著；玩家不會自動離開。站在 `DIG.range` 內按 F（`Player._try_interact`，撿東西與寶箱優先）→ `request_exit`：發起投票（`vote_by`、`vote_left = VOTE.time`、`vote_yes` 含發起人；多於一人才發 `vote:started`），投票中按 F 算同意。`InputCmd.BTN_VOTE_YES`（Enter）/ `BTN_VOTE_NO`（Esc）在 `Player.update` 開頭處理（倒地、暈眩也能投），`InputCollector.vote_pending`（main.gd 每步依 `awaits_vote` 設定）時才送出，並攔下 Esc 不開選單。有人反對 → `vote:canceled`、取消；沒死的人全部同意或時間到 → `vote:passed` → `floor_num >= DIG.last_floor` 時 `World.win()`（通關，`victory_delay` 後 `game:victory`），否則 `World.next_floor()`。單人按 F 立刻通過。`World.next_floor()`：層數 +1、基礎難度 = (層數 − 1) × 10、移除所有非玩家實體、`arrive_floor` 回出生點、`_populate_floor`（事件歸零 → 寶箱 → 怪群）、帶著屍體的死者生冤魂、發 `floor:started`。實體 id 不重來（客戶端照常增減鏡像）。`Player.descended`（走進出口的舊做法）現在沒有地方設成 true，畫面與快照的支援先留著。
- **Boss 獎勵**：挖墳地圖的 `on_boss_defeated` 不通關，在 Boss 旁掉一個大寶箱稀有度的道具（`boss:reward`）；武器與 50 金幣照 `on_enemy_died`。
- **屍體與冤魂**：多人時真的死亡（`_on_died`）→ `World.drop_corpse`：`ItemPickup`（item_id `&"corpse"`、`corpse_of` = peer id）。撿起 → `Player.add_corpse`：背包條目 uid `corpse_<peer>`、id `&"corpse"`（`ItemDefs` 的 kind `&"corpse"`，形狀 r6，不算生效道具）；丟出來還是屍體。換層時 `corpse_carrier` 找到就 `_spawn_ghost`（`EnemyDefs` 的 `ghost`，MeleeEnemy，`ghost_of`，出生點 10~14）；冤魂死亡 → `on_ghost_defeated`：移除屍體、`Player.resurrect`（冤魂位置、30% 血、短暫無敵）。客戶端 `net_sync_life` 支援死亡 → 復活。
- **快照**：世界加 `W_FLOOR`、`W_EVENT`（[狀態, 進度, 秒數, 基礎難度, 正在生怪, 投票發起人, 投票剩餘秒數, 同意的 peer id]）；玩家 extra 加 `P_DESCENDED`；地上道具 extra 第 3 欄是屍體主人。挖墳點在 `World.load_map` 就設好（客戶端預測要判斷挖不挖得到）。
- **畫面**：挖墳點土堆 + 墓碑（土堆隨進度變矮），打開後是黑洞 + 發光環與光；`WorldLabels` 顯示「[F] 按住挖墳」、「挖墳 N%」、「出口：[F] 通關 / 前往第 N 層」、冤魂說明；HUD 右上「第 N 層 · 難度 D」與事件橫幅（開挖、Boss 發現你、擊敗 Boss、挖開、有人反對）；HUD 上方中央的挖墳進度條（事件進行中所有人都看得到，說明噴怪間隔），下面是投票橫幅（「P1 想通關（1 / 2 同意，12 秒）[Enter] 同意 [Esc] 反對」，自己同意後不再提示按鍵）與 Boss 血條；冤魂是半透明偏藍的騎士（`SkinnedRig.set_ghost`）；挖墳姿勢彎腰雙手往下挖。

## §16 試玩回饋：效能、提示、牆後剪影、道具效果（v0.30.0~v0.33.0）
- **休眠怪群**（v0.30.0）：`Entity.fixed`（`Enemy.dormant` 的 setter 同步）＝不積分；`SimPhysics.separate` 固定的不主動找鄰居、不被推，會動的一方退開全部重疊。`Enemy.update` 休眠時只推進 `fsm.time`。
- **新手提示**（v0.31.0）：`ui/hints.gd` 每幀讀 World 判斷條件（客戶端讀鏡像也一樣），看過的存 `user://settings.cfg` `[hints] seen`；`--seconds` 自動驗證不存。文字在 `defs/hint_defs.gd`。開著背包時提示框放在屬性面板與背包中間，太長就換行（`HUD._place_hints`）。
- **牆後剪影**（v0.32.0）：角色材質 `stencil_mode = CUSTOM`（寫入 `XRAY_STENCIL`），`material_overlay` 是不做深度測試、模板值不等於它才畫的純色材質（`WorldView.XRAY_SHADER`）。玩家一直開；怪物在 `_xray_needed`（往相機方向取樣地形高度，每 `LOS_INTERVAL` tick）成立時才開。地上的圈與扇形（`XRAY_SKIP`）不畫。
  - 投射物（2026-10-26 使用者要求：箭飛到牆後要跟怪物一樣看得到）：箭與魔彈也有剪影，顏色看發射者（怪物紅、自己藍、隊友綠），每個 tick 都判斷（飛得快、數量少）；視野規則不變（視野外、被牆擋住視線的照樣不畫）。
  - **寫模板值的材質要共用**：同一種外觀每個實體各自一份 `StandardMaterial3D` 時，寫了模板值後每一份都要編一次著色器（網頁版每射一箭卡 30~40 ms，預熱後多編 34 個程式）。箭共用 `DarkFantasy._projectile_kit` 的材質、魔彈依顏色共用（`WorldView._orb_materials`），預熱後只剩 0~3 個；`check.gd` 檢查同顏色的投射物共用材質。
- **道具效果**（v0.33.0）：`sim/item_effects.gd`。`Combat._apply_damage` 對玩家方的一般攻擊：先乘「對滿血敵人」的攻擊力倍率（`Stats.value_with_pct`），命中後 `on_hit`（連鎖閃電、中毒、冰凍），打死後 `on_kill`（爆炸、回血、擊殺計時）。道具效果造成的傷害帶 `proc = true`：不爆擊、不觸發 `on_hit`，打死怪仍觸發 `on_kill`。低血、擊殺後的加成由 `Player._tick_timers` → `update_player` 以來源 `cond:<uid>` 套上。中毒 / 冰凍狀態在 `Enemy`（權威端推進），畫面看 `anim.frozen / poisoned` 染色（`SkinnedRig.set_status_tint`）。數值在 `ItemDefs.PROCS`；已接上的在 `IMPLEMENTED_CONDITIONS / IMPLEMENTED_TRIGGERS`；寶箱與 Boss 獎勵用 `LootDefs.drop_pool`（只抽全部接上的，沒有就往下一級）。
- **已知限制**：客戶端不知道「擊殺後攻速 +30%」（擊殺只在房主結算），自己的出招速度在 3 秒內會比房主慢，房主的判定為準。

## §17 遊玩紀錄與回報（v0.34.0；複製回報 2026-10-26）

## §24 主手與副手（Build 改版第 2 步，2026-10-30 許家慶決定，招式數字 Claude 暫定）
- 取代 2 格裝備欄與 X / 滾輪切換：`Loadout.weapon_slots` = [主手, 副手]（`Loadout.MAIN / OFF`），主手一定有武器。

  - 長劍沒有副手時右鍵**蓄力突刺**（`chargedThrust`）：按住蓄力最多 0.8 秒（移速 ×0.5），放開往準星衝 2 → 5 單位、0.25 秒內每步判定前方 1.6 / 90°（每隻一次）150% → 300%、擊退 8，冷卻 5 秒，可翻滾取消。衝刺用 knockback 衝量，衝量依每步的衰減反推（實測沒蓄 2.06、蓄滿 5.00 單位）。

- **詞條**：主手套稀有度倍率＋詞條（屬性來源 `&"weapon"`）；副手只套詞條（`&"offhand"`，`WeaponDropDefs.offhand_mods`，Claude 暫定）。

## §26 部位決定發動時機（Build 改版第 4 步，2026-10-30 許家慶決定）
- 使用者決定：只有**命中類**（雷鳴符文、淬毒刀刃、霜之心、永恆之焰）與**普攻類**（袖中飛刀、裂空之刃）看部位（`ItemDefs.PART_TIMED_TRIGGERS`）；擊殺、受傷、翻滾、定時、保命與數值效果放在哪個部位都照原本的時機。**一件道具跨好幾個部位時每個部位各算一次**。
- 時機（`ItemDefs.PART_TIMING`）：攻擊部位 = 每次命中 / 普攻出手（同以前）；末端 = 連段最後一下（命中的 hit 帶 `finisher`，`MeleeSwing` 的終結技；出手看 `is_finisher`）；防禦部位 = 格擋或招架成功（`Combat._apply_damage` 擋下後 `ItemEffects.on_block`，命中類打向攻擊者、傷害用武器基礎傷害 × `BLOCK_HIT_DAMAGE_PCT`（Claude 暫定 100%），普攻類往面向射出）；握柄、寶石座不發動。
- 跨部位（劍尖 + 刃）的連段最後一下：有機率的各擲一次骰；有內部冷卻的（飛刀、斬波）同一下第二次被冷卻擋掉，等於只發動一次。
- `Loadout.items` 每件多記 `parts`（碰到的部位字元，`Inventory.parts_of`），`refresh_items` 每次重算（同一隻手裡搬位置也會呼叫）；`ItemEffects.procs_of(p, on, part)` 只算碰到那個部位的。
- 自動擺放（按 F 撿、換武器搬道具）：武器格子的 `Inventory.find_spot` 先找合偏好的位置——看部位的道具要碰到攻擊部位，其他道具不佔攻擊部位、末端、防禦部位；沒有才用第一個放得下的（Claude 暫定）。
- Tab 說明：鑲上的看部位道具多一行「發動：連段最後一下命中時」或「不發動（…）」（`ItemDefs.timing_line`）；道具說明改寫成「發動時 X% 機率…」。
- 測試：連鎖閃電、中毒、飛刀改成一直打到觸發（只有碰到攻擊部位的才算，武器格子放不下疊到 100% 的件數）；部位的檢查在 `LootChecks.check_item_part_timing`（末端用擲骰次數驗證：一般命中 1 次、連段最後一下 2 次）。

## §27 羈絆（Build 改版第 5 步，2026-10-30 許家慶決定；門檻、每階效果與數字 Claude 暫定）

- **效果**（`sim/bond_effects.gd`，使用者照 A 表同意）：

## §29 寶石座技能與輔助道具（Build 改版第 7 步，2026-10-30 許家慶決定；技能數字 Claude 暫定）
- **寶石座只放技能、技能只放寶石座**，而且只能鑲在技能寫的武器上（`Inventory._fits_cells`、`SkillDefs.can_socket`；背包什麼都放得下）。技能是 `ItemDefs` 的 `kind &"skill"` 條目（1 格，名稱、說明在那邊），動作與數字在 `SkillDefs.SKILLS`（同一個 id）。技能不算生效的道具（`Loadout.items` 不含）。
- **按鍵**：數字鍵 1~4 = 主手、副手寶石座上的技能（主手先，各自由上到下、由左到右，`ActiveSlots.gems`），Q = 治療藥水（`ActiveSlots.HEAL_INDEX`，`InputCollector` 的 slot_5）。技能欄照寶石座的內容重建（`ActiveSlots.signature`）。
- **插火把**：火把出廠就鑲在寶石座（`WeaponDefs` 的 `slot_skill` → `WeaponDropDefs.add_builtin_skill`），可以拿下來換別的技能；次數照舊記在鑲著它的那把武器上（`slot_charges`）。
- **技能清單**（使用者照表同意，參考 POE2 依武器分）：每種武器 3 個專屬技能，共 27 個（長劍：旋風斬、衝鋒斬、劍氣；匕首：背刺突襲、扇形飛刀、煙霧彈；火把：火焰新星、火瓶、火焰衝刺；木盾：盾衝、嘲諷、震盾；法杖：冰霜新星、隕石、閃電鏈；驅魔權杖：聖光柱、骸骨衛士、祝福；短弓：連珠箭、後跳射、閃電箭；長弓：箭雨、狙擊、冰霜箭；鐵鏟：震地、甩土、掘地）。嘲諷原本寫「護甲 +50%」，玩家護甲常是 0 加百分比沒用，實作改成受到的傷害 −33%。
- **行為**（`sim/skill_behaviors.gd`）：16 種共用行為（一圈、扇形、衝刺、瞬移背刺、射擊、後跳射、落點打擊、箭雨、閃電鏈、煙霧、嘲諷、召喚、祝福、掘地…）照技能資料的參數做。傷害 = 手上武器基礎傷害 × damage_pct（`Player.pct_damage`）× 等級倍率。位移兩邊都做（本機預測），傷害、投射物、召喚、地面區域只在權威端；晚一點才發生的（隕石、箭雨、連珠箭、狙擊蓄力、分裂）排進 `World.delayed`（換層清掉）。投射物結束時的效果（跳電、炸開暈眩 / 冰冷、落地一攤火）在 `Projectile.skill_fx` → `SkillBehaviors.projectile_end`。
- 新的怪物狀態：技能暈眩 `Enemy.stun`（Boss 不會）、被嘲諷 `taunt_id / taunt_timer`（`nearest_player` 只追他，Boss 不會）、煙霧 `blind_timer`（打玩家多一半打偏，`Combat`）；煙霧彈是 `GroundZones` 的 `smoke`（裡面的玩家閃避 +30%）。
- **等級**（`Player.skill_levels`，進快照）：技能遺物選到身上（兩隻手的格子或背包）已經有的技能就升 1 級，最高 5 級；每級傷害 +20%、冷卻 −10%（`SkillDefs.LEVEL`）。
- **技能遺物**：祭壇 20%、石棺 35% 開出技能遺物（`LootDefs.RELIC.skill_chance`；Boss 固定道具遺物）；地上是金黃色的方塊。選項從全部技能抽（`SkillDefs.relic_pool`，不含插火把），卡片寫能用的武器、標籤、冷卻與「已有：升到 N 級」。
- **輔助道具**（4 個，在道具遺物的掉落池裡，`ItemDefs.support_of`）：鑲在寶石座上下左右、標籤相符才有效（`ActiveSlots.supports_of`）。分裂（範圍 / 投射：0.25 秒後再放一次 60%）、延長（範圍 / 投射 / 移動：範圍與距離 +50%）、火焰化、霜化（範圍 / 投射 / 近戰：改成火焰 / 冰霜傷害，算那個羈絆）。
- 檢查：「寶石座技能」（`tests/skill_checks.gd`：鑲嵌規則、按鍵順序、27 個技能都放得出來而且有效果、等級、技能遺物、輔助道具）。

## §30 武器詞條與鍛造祭壇（Build 改版第 8 步，2026-10-30 許家慶決定；詞條數字、偏向、祭壇數量 Claude 暫定）
- 詞條種類照武器格子 artifact：**詞條都跟羈絆有關**，原本 10 條數值詞條拿掉（稀有度的基礎倍率 `RARITY_BASE` 照舊）。資料在 `WeaponDropDefs.AFFIXES`（`kind`、`bond`、`desc`、權重 `w`、屬性 `mods`）：
  - `bond` 羈絆 +1（5 條）：這把武器本身算那個羈絆 1 件；`Loadout.refresh_items` 算完道具再加（`WeaponDropDefs.bonds_of`），主副手各算。
  - `enh` 羈絆強化（每個羈絆 2 條，權重各 0.5）：新屬性 `poise_gain`（失衡值累積）、`burn_max_stacks` / `chill_max_stacks`（加在羈絆的層數上限上，疊滿爆炸 / 凍結也看新的上限，`BondEffects.burn_cap / chill_cap`）、`freeze_time`、`parry_window`（`WeaponBehaviors.ShieldBlock` 的判定時間乘它）、`wisp_count`（`wisp_plan` 多幾顆秘術，第 3 階照樣加倍）；另外沿用擊退、燃燒傷害、護甲、鬼火傷害。
  - `cvt` 屬性轉換：`convert_fire` / `convert_cold` 各 50%。`Combat._apply_damage`：玩家的非道具物理傷害只打 1 − 合計（最多 100%），扣完血之後再打轉換的部分（`Combat._converted_damage`：這一下的基礎傷害 ÷ 物理傷害 × 屬性傷害，主要那一下爆擊就跟著乘爆擊傷害；是 proc，不再觸發命中道具，但會疊燃燒 / 冰冷）。
  - `imp` 印記格（藍以上，`min`；第 8b 步）：`make` 時每條從武器格子挑 `IMPRINT.cells`（2）格（不含寶石座、不重疊，`roll_imprints`），存在實例的 `imprints` [{bond, cell}]；合成時重擲。道具碰到同羈絆的印記格（任一格）倍率 `IMPRINT.mul`（1.5，`imprint_mul`）：`Loadout.items` 每件多記 `mul`，屬性數值加 / 百分比 × 1.5、相乘的取 1.5 次方（`ItemDefs.stat_mods`），有機率的觸發機率 × 1.5（`ItemEffects.procs_of`）；沒有機率的觸發、條件加成、能力（鬼火燈顆數）不變。快照：`to_array` 第 7 欄 [[羈絆, x, y], …]。介面：武器格子上羈絆顏色的粗框＋角落菱形，滑鼠停在上面的道具多一行「在印記格上：效果 ×1.5」。
  - `branch` 分支（紫橘，`min`；第 8c 步）：改寫一個羈絆的規則，一把最多 1 條（抽到一條就把其他分支移出池子；合成兩把各留一條分支時只留第一條）。手上兩把的分支在 `Loadout.branches`（`BondEffects.has_branch`），數字在 `WeaponDropDefs.BRANCH`（artifact 的例子挑第一版 5 個羈絆的）：
    - 沉重（物理）：屬性 攻速 ×0.7、失衡值累積 ×2.5（失衡要物理第 2 階）。
    - 爆燃（火焰）：`BondEffects._burn_rush`：燃燒不疊層；打中燃燒中的怪先一次打出剩下的燃燒傷害（每跳 × 剩幾跳，火焰、no_status），再重新點 1 層；所以不會疊滿爆炸。
    - 冰棺（冰霜）：疊滿凍結時改成 `coffin_time`（3 秒）、`Enemy.ice_coffin`（`apply_freeze` 會清掉，`add_chill` 凍完再標）；打冰棺不碎冰（`pre_hit`），受到的傷害 `coffin_share`（50%）分給 `coffin_radius`（3）內最近 `coffin_targets`（4）隻（冰霜、no_status、帶 `coffin_share` 不再分）。畫面：動畫狀態 `coffin`（快照照送）→ 染冰白 `WorldView.COFFIN_TINT`、全身冒冰晶，和一般冰凍的深藍分得開。
    - 反擊架勢（防禦）：`Player._try_counter`（`try_block` 沒在格擋時）：主手沒有盾的招架、在 `attack` 動作開始後 木盾判定時間 × `counter_window_mul`（0.5）× 招架判定時間 內、正面 `counter_arc`（120°）的能格擋攻擊 → 算招架成功（不扣血、`player:blocked` perfect、`BondEffects.on_parry`），沒有盾反那一下。
    - 星位（鬼火）：權威端翻滾開始時記 `Player.wisp_anchor`；`OrbitWisp` 繞 `Player.wisp_center()`（錨點離自己超過 `star_leash` 20 就回到身邊），停在錨點時沒有第 2 階也會定時衝向附近的怪（砲台）。
- 抽法（`roll_affixes`）：詞條數照舊 = 稀有度序號、不重複；依權重一條一條抽，武器偏向的羈絆（`BIAS`，artifact 的表只留第一版 5 個羈絆）權重 × 3。
- 主手：稀有度倍率＋詞條（`&"weapon"`）；副手只套詞條（`&"offhand"`）。這些屬性在屬性面板只在不是基礎值時顯示（見 開頭「屬性面板」）。
- **鍛造祭壇**（`sim/forge.gd`，kind `forge`，`World.forges`）：地圖的 `forge_count`（地圖 A 1 座），`World._place_chests` 排在祭壇 / 石棺後面用同一套規則（寶箱的位置和沒有它時一樣）；不擋路、不能被打、可以一直用；快照 extra `[]`（`NetCodec.KINDS` 最後加 `forge`）。按 F（`Player._try_interact`：道具 → 遺物 → 祭壇 / 石棺 → 鍛造祭壇）發 `forge:opened`，本機的 HUD 發 `forge_opened` → `main._open_inventory` 打開背包。
- **合成**（`Loadout.merge`）：除了同種、同稀有度，還要站在鍛造祭壇旁（`World.near_forge`：身體邊緣到祭壇邊緣 `LootDefs.FORGE.range` 3 單位內，比 F 寬，開著背包走一點還能合），否則發 `weapon:merge_denied`（`reason: "forge"`，HUD 寫「要站在鍛造祭壇旁才能合成」）。`OP_MERGE` 多兩個選填欄位：兩把各要留的詞條（不是那把的不算），結果先放這兩條、其他重抽（`roll_affixes` 的 `keep`）。
- **介面**：背包裡拖武器到可以合成的武器上，旁邊寫「合成」（不在祭壇旁是紅字「合成（要在鍛造祭壇旁）」）；兩把都有詞條而且在祭壇旁時不直接送，`InventoryPanel.merge_choice` → `ui/forge_panel.gd` 在背包左邊列出兩把的詞條（羈絆顏色，預設各自第一條），點選後按「合成」送出；背包關掉、離開祭壇、有一把不見了就關掉。白色沒有詞條，直接合成。地上顯示「鍛造祭壇」，按得到時加「[F] 合成武器」；模型是石台＋鐵砧＋發光的炭火（`WorldView._create_forge`，開場預熱）。
- 檢查：武器掉落與詞條（`LootChecks.check_weapon_affixes`：詞條都跟羈絆有關、偏向比例、keep、主副手生效）、羈絆效果裡的分支（`BondChecks._check_branches`：紫橘才有、最多 1 條、5 個分支的效果）與印記格（`BondChecks._check_imprints`：藍以上才有、格子合法、×1.5 與還原、快照）、武器的背包操作（`check_weapon_merge`：不在祭壇旁不能合、各留一條、走遠不算）、羈絆效果（`BondChecks.check_weapon_affixes`）、背包介面（`ViewChecks.check_forge_panel`）、連線武器（房主旁邊放祭壇）。測試放祭壇用 `CheckKit._forge_near`。
